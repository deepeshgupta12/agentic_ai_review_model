# Contracts v1

The versioned implementation contracts from Step 02. The backend (Pydantic models, MongoDB validators), the web app (types generated from OpenAPI) and the agents (structured outputs) all derive from these files. Where they disagree with prose in `docs/`, these files win; change the contract, the docs and the fixtures together.

## Files

| File | Holds |
|---|---|
| `common.schema.json` | IDs, revisions, hashes, time, unknown dates, text/time anchors, calibrated confidence, error envelope and every status list |
| `catalogue.schema.json` | Project input file (1.1), project record, configuration with approved aliases, alias proposals (D17) |
| `sources.schema.json` | Source policies, global source revisions, project-source links, media segments, connector state, origin clusters |
| `evidence.schema.json` | Evidence spans, atomic claims, findings |
| `content.schema.json` | Frozen page payload, dependency manifest, content revisions, review decisions |
| `publication.schema.json` | Project/locale control document and publication operations |
| `operations.schema.json` | Jobs, workflow runs, agent runs, audit events, deletion requests, evaluations, users, public corrections |
| `agents.schema.json` | Task envelope and the output of each model-backed agent (A01–A10) |
| `api.schema.json` | API request bodies and response views |
| `routes.json` | The 47 API operations with roles; source of `openapi.json` |
| `openapi.json` | Generated by `scripts/build_openapi.py`; never edit by hand |
| `state_machines.json` | Allowed transitions and actors for every status; classifications |
| `journeys.json` | The mandatory user journeys with actor, API call and state path |
| `fixtures/` | Synthetic valid/invalid cases, hashing and anchor vectors, approval and public-read rule cases |

Human-readable views: [docs/09-screen-specifications.md](../../docs/09-screen-specifications.md) and [docs/10-journeys-and-states.md](../../docs/10-journeys-and-states.md) (generated).

## Conventions

- **IDs** are opaque strings: a three-letter type prefix and a ULID, e.g. `prj_01J…` (D19). Connector IDs and policy families are snake_case names.
- **Revisions.** Immutable records are keyed by `(id, revision)`, and every reference names both. Mutable records carry a `version` that each write must state.
- **Time** is RFC 3339 UTC with `Z`. A date that may be unknown is a `DatedValue` whose `unknown` status forces a null value; collection time is never substituted.
- **Text anchors** are Unicode code points over NFC text (D24). API views add UTF-16 offsets for the browser.
- **Confidence** is null unless an evaluation calibrated it; model self-ratings are never stored as confidence.
- **Status lists** are defined once in `common.schema.json`. Each has a state machine or a classification in `state_machines.json`; the checker fails on inline copies.
- **Actors** come from the session. No request body accepts an actor or user ID, and review decisions are always made by a person.

## Canonical hashing (D23)

Payload and manifest hashes are SHA-256 over the RFC 8785 (JCS) serialisation, written `sha256:<hex>`. Before hashing, the backend rejects non-integer numbers, integers beyond ±(2^53−1) and text or keys not in Unicode NFC, so Python and TypeScript always agree. Manifest arrays are sorted by `(id, revision)`. `fixtures/hashing.json` holds the shared vectors; `scripts/jcs_check.mjs` re-checks them with an independent JavaScript implementation.

## Agent outputs

Output schemas use only what Claude structured outputs support: closed objects, every property required (null instead of optional), no length, number or pattern constraints, no recursion. `contract_tools.bundle_schema` inlines shared definitions into one self-contained schema for the API call. After parsing, the backend still validates business rules, including that every ID a model returns was in its input. A00 is deterministic and has no model output. Models report `completed`, `insufficient_evidence` or `needs_review`; only the backend records `failed`.

## Baseline gaps resolved (docs/02)

| Gap in the baseline exchange schema | Resolution |
|---|---|
| 1. Source identity mixed with project association | `SourceRevision` (global) plus `ProjectSourceLink` per project and segment |
| 2. IDs pointing to mutable meaning | `(id, revision)` references everywhere; `DependencyManifest` lists exact revisions |
| 3. Publication as a summary only | `PublicationOperation` with idempotency, revalidation and rendered-revision verification |
| 4. No jobs, leases, cursors, media, policy versions, evaluations | `Job` (lease + fencing), `ConnectorState`, `MediaSegment`, `SourcePolicy` versions, `EvaluationRun` |
| 5. Unknown publication dates | `DatedValue` with `unknown` status |
| 6. Approval not bound to exact content | `ContentBinding` in `ReviewDecision` (hashes, epoch, state version) |
| 7. Empty evidence forced a summary | `WorkflowRun` stage `insufficient_evidence` with no content revision |
| 8. Limited status enums | Separate status lists with state machines, extended on purpose (e.g. `cancelled`, `changes_requested`, `superseded`) |
| 9. Text coordinate units | Code-point anchors with UTF-16 views (D24) |
| 10. Confidence, transcription quality and timestamp precision mixed | Separate `Confidence`, `quality_flags` and `TimestampPrecision` |

The baseline files (`contracts/client-data-*.json`) stay as history. Notable differences: `micromarket`, `client_id`, `page_url` and RERA references are optional; model IDs come from configuration, not fixtures.
