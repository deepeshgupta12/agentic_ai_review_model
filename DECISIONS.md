Window text is the cues' text unchanged; its payload is erasable. **Matching:** a window that names a project is matched on its own words (comparison videos split per project). A window that names none inherits the video's accepted match, like a comment (D42): with one matched project it is accepted, with several it goes to review. If the video's match is undone, inherited windows return to review. Speech evidence is governed by `spoken_video_content`. **Language:** tags are hi, hi-Latn and en. Flags: code-switching, music, low confidence, low audio quality and auto-generated captions. Every number, amount, area or date in machine-made text is flagged `numbers_uncertain` for a person. **Translation (A04):** windows that are not entirely English get an English translation, stored apart from the original. The backend keeps a translation only if every number in the original appears in it and a negation is still a negation; otherwise it is rejected, audited and left for a person. **Contracts:** sources 1.3.0 (routes `public_captions` and `public_audio_transcription`; caption-based transcription with `caption_kind`; flags `auto_generated_captions` and `low_confidence`) and operations 1.2.0 (job kind `process_media`). **Policies:** spoken_video_content v2 applies D33. youtube v3 moves the "no downloading" condition to spoken_video_content; its rights are unchanged | Proposed by implementer (Step 06 item Z1) |
| D48 | Speech-to-text model and media worker resources. faster-whisper `large-v3-turbo` (int8, CPU) by default (`WHISPER_MODEL`). On the synthetic speech set it kept 19–20 of 22 key facts against 13 for `small`, with Hindi word error about 27–34% against 35%. It runs at about 1–2× real time natively on the M1, and about 3–11× in Docker (Linux arm64), so a 60-second short takes about 2–11 minutes. Transcription runs in its own `media-worker` (image with ffmpeg and the media libraries; `WORKER_ROLE=media`): capped at 2 GB and 3 CPUs, a 1 GB in-memory scratch disk emptied after each job, and model weights cached in a volume. `oom_score_adj` makes the kernel kill this worker before anything else, and MongoDB last. MongoDB's cache is capped at 0.75 GB; its default took 2.1 GB of the 4 GB VM during tests. On 1 Oct 2026 a 3 GB model test in the 4 GB Docker VM (shared with other stacks) got MongoDB killed for lack of memory; it recovered with no data lost. The main worker (`WORKER_ROLE=general`) never takes media jobs. faster-whisper's own decoder is bypassed (it is incompatible with av 19); ffmpeg's 16 kHz mono WAV is read directly. Debian packages are fetched over HTTPS because port 80 is blocked on this network | Proposed by implementer (Step 06 item Z2) |
| D49 | Frames and on-screen text (Step 06.5) are not extracted in Release 1.0. Speech carries the reviews. Renders and undated footage cannot prove construction status (docs/06). Each frame would need a Claude vision call and a new review path. The contracts keep the `on_screen_text` and `frame` modalities, so they can be added later on a recorded decision. Metadata stays out of evidence | Proposed by implementer (Step 06 item Z3) |
